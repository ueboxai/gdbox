# GDBox：从虚幻盒子分叉迭代

> 状态：进行中（2026-10-14 开始）。
> 前身：从零写的 GDBox 原型，设计稿见 [GDBox原型设计-2026-10-14.md](GDBox原型设计-2026-10-14.md)，代码留在本机 `H:\UnrealAgent\_gdbox-v0`（不发布）。

## 为什么换路子

原型是从零写的：只有 6 个组件、只抄了配色，界面和交互跟虚幻盒子对不上。用户要的是**同一家公司的两条产品线**：设计语言统一，外壳、交互、组件一致，只是面向的引擎不同。

所以改成：

1. 把虚幻盒子源码（uebox-pub `b6b4aab`）整体复制过来，作为第一个提交；
2. 删掉虚幻专属的内容；
3. 原有外壳和交互保留，迭代成 Godot 版；
4. 原型里已经跑通的 Godot 能力，作为模块迁进来。

「脱钩」指运行时不依赖虚幻盒子的配置和数据，不是不复用代码。

## Agent 底层

虚幻盒子的 agent-v3 本来就建在 pi 上（`@earendil-works/pi-agent-core` + `pi-ai`），不是自研内核。所以「用最新的 pi」落实为**把 pi 升到最新版本**（1.0.0 → 1.2.0），而不是推倒重写。界面和 Agent 之间的协议（`agent-v3:*` IPC、`AgentV3Event`）一个字不动。

## 工作室模式真机（2026-10-15）

两局 `/team`，deepseek-flash 当制作人，队员模型由制作人挑。

| 局 | 结果 |
|---|---|
| 接金币（CoinCatch） | 招了程序、审核两人；约 35 分钟交付，独立验收员 PASS（时间到赢、碰炸弹输、R 重开都实测过）。审核员抓到一个真 bug：`collected` 信号从没 emit，接不到金币 |
| 打砖块（Breakout） | 新构建；制作人建完工程就 `set_session_project` 挂上（顺带进了项目库），交回即存快照；四个队员并行（像素、音效、程序、审核），按契约文档分工。中途被停下，没跑到交付 |

第一局暴露、已修的问题：

- 文件锁和编辑器排队在分叉时随虚幻的注册表一起删了，提示词却还在承诺 → 接回来，锁的粒度换成工程里的文件（`res://` 路径，`tools/godotLocks.ts`）
- 制作人的锁跟着整局走 → 它碰过的文件队友到交付前都改不了（程序等 main.tscn 等了 14 分钟）。现在制作人的锁只占一次调用
- 模型新建的工程挂不到对话上 → 快照、`team_status` 都找不到工程。`set_session_project` 认工程目录路径，没登记的顺带登记进项目库
- 导入标记记的是完成时刻 → 导入进行中队友写进来的图永远不再导入（bomb.png「资源不存在」）。改记开始时刻，同工程导入排队
- `gen_music` 只说「Godot 导入时会识别循环点」→ 验收员把 `loop_mode=0`（从 WAV 读）当成没循环，团队随后把无缝循环点改坏了。回话改成写清运行时的值和核实方法
- `godot_run` 的 watch 读不了子节点数 → 支持不带参数的 `get_/is_/has_` 方法
- 办公室招牌、灰人偶、节点图换成 Godot 的；编辑器看护改成重开 Godot；工程清点按扩展名
