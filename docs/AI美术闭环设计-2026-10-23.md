# AI 美术闭环设计：像素清理、色板、截图评审、光照

> 状态：设计稿，未实现（2026-10-23，已经过一轮专家评审修订）
> 涉及：`godot/aigc/{style,sprite,tileset,pixels}.ts`、`tools/godot-asset/*`、`tools/godot/runtime.ts`、`core/team/reviewLoop.ts`、`core/team/snapshots.ts`、`core/editorScreenshotScope.ts`

## 要解决的问题

素材生成这一层已经比较完整：`art_style` 定画风，`gen_sprite` / `gen_sprite_video` / `gen_tileset` 出图，生成后用 `applyPalette` 映射到调色板。
但 AI 做的游戏画面仍然一眼能看出是 AI 做的，原因有四处：

1. **像素是假的。** `modeDownsample` 按帧高推算缩放比例，不检测 AI 原图的像素格和相位，产生双像素线、锯齿台阶和孤立噪点；描边有的有、有的没有。
2. **调色板映射太粗。** 用 RGB 最近色硬映射：暗蓝映射成灰，相邻两级明暗被并成一色；非像素风会出现色块断层；只处理生成的素材，不管工程里的其他图。
3. **Agent 看不到画面，也不知道该怎么看。** `godot_screenshot` 能截一帧，但没有评分标准、没有参考对比，也不保留"目前最好的版本"。2026-10-20《缝天旅人》的首房美术样板来回改了 R1–R8 八轮。
4. **光照是画死在图里的，方向各不相同。** 场景里也没有统一的光源和色调。

外部参考（链接见文末）：
- GameDevBench：所有任务类型中，2D 美术类成功率最低（33%，玩法类是 51%）；加入截图反馈后，GPT-5.4 的成功率从 41.1% 升到 52.0%。
- GameUIAgent：独立视觉模型评审，每轮只修得分最低的两项，并保留历史最好版本，平均 +0.96 分；初稿分数越高，收益越接近 0（r = −0.96）。不同评审模型之间几乎不一致（ICC 0.021）。

## 专家评审的结论

主美、Godot 技术美术、色彩与插画专家、像素美术师各评审一次，再交叉反驳一轮。相对初稿的主要改动：

| 初稿 | 修订后 | 理由 |
|---|---|---|
| 法线贴图在第一版 | 推迟，改为可选，盲比赢了才进 | 距离场做出的是"枕头光"，本身就是 AI 图的典型毛病；32px 上量化成 8 方向，灯一转边缘就闪（四人一致） |
| dynamic 模式出平光图 | 保留体积明暗，只去掉投影 | 平光图在没有法线时画面更平 |
| 在截图上算调色板偏离率、颜色数、灰度直方图跨度 | 偏离率只对素材本身算；另外两项删除 | 灯光和 CanvasModulate 会改变颜色；缩放和抗锯齿让颜色数暴涨；一行白字加黑描边就能撑满直方图跨度 |
| 光照一致性交给视觉模型 | 色温由代码算，光向只让视觉模型抽查 | 视觉模型认不准光的方向 |
| 离散的 16 色调色板 | 按色相分组的色阶（ramp），像素风和非像素风两套规则 | 按频次取色会丢掉最亮和最暗；硬映射会把相邻两级明暗并成一色 |
| 没有像素清理 | 第一版必须做 | 假像素是像素风最先暴露 AI 味的地方 |
| 评分维度从构图开始 | 剪影 → 明度与焦点 → 比例与像素密度 → 线条与风格 → 色彩 → 细节 | 主美最先看剪影和画法是否统一 |
| 后处理放在"不做" | LUT 后处理提前到截图评审之前 | 统一颜色最便宜的手段 |

## 1. 像素清理、OKLab、描边、光向

### 1.1 像素格检测（像素风）

现在 `modeDownsample` 的比例由 `frameHeight / 最高帧` 决定。AI 原图的"像素"实际是 6.5–8.5 个真实像素一格（见代码注释），比例不是整数时就会切出双像素线。

改为：
1. 从水平和垂直方向的颜色跳变间距估计格宽和相位（间距直方图或自相关）。
2. 每格只取中心 60% 的区域，**先映射到调色板，再投票**。现在的做法是先按 5 位分桶投票、再映射，相近色互相分票，结果被边缘混色占了多数。
3. 估计出的高度和 `frameHeight` 相差超过 15% 时只报警告，不做二次缩放。
4. 格子不规则、估计不可靠（自相关峰值不明显）时，退回现在的众数降采样，并在返回文本里说明。

### 1.2 像素清理

降采样之后依次执行：

| 步骤 | 规则 | 默认 |
|---|---|---|
| alpha 二值化 | 映射前先二值化，避免半透明边缘不被映射、形成色晕 | 开 |
| 去孤点 | 8 邻域里没有同色，且和多数邻色 ΔE 很小时，换成多数邻色；高对比的高光保留 | 开 |
| 去 L 角 | 描边上三个像素成 L 形时删掉拐角那个，只留 1px 的对角连接 | 图块开，精灵关（见待实测 2） |
| 外描边统一 | 1px 外描边，颜色取调色板最暗色；原图已有描边时只统一颜色，没有才补 | 像素风开 |

推迟到以后：锯齿检测（线段步长序列不单调时报告）、帧间一致性（同一动画各帧颜色数和描边色一致）、内描边 selout（内线用所在色阶最暗的一级）。

`StylePack` 新增：

```ts
outline?: 'none' | 'outer'           // 像素风默认 outer
cleanup?: { lCorners?: 'off' | 'tiles' | 'all' }  // 默认 tiles
```

### 1.3 颜色距离改用 OKLab

`applyPalette` 和 `extractPalette` 的距离计算都改用 OKLab ΔE。单测：暗蓝不被映射成灰。

### 1.4 统一光向和色温（提示词）

```ts
lighting?: {
  mode: 'baked' | 'dynamic'
  direction?: 'top-left' | 'top' | 'top-right'   // 默认 top-left
  keyColor?: string                              // 主光色，默认 #ffe2b8
  shadowHue?: number                             // 阴影色相，默认 250（OKLCH）
}
```

- `baked`：提示词加上 `lit from the <direction>, warm highlights, cool blue-violet shadows, no pure white highlights, no pure black or gray shadows`。
- `dynamic`：提示词加上 `keep form shading, no cast shadows`。保留体积明暗，只去掉投影，光照交给引擎。

## 2. 代码指标

放在新文件 `godot/aigc/metrics.ts`，`art_review` 和 `art_palette_check` 共用。所有指标都在**素材本身或无光照截图**上计算，不在最终截图上计算。

| 指标 | 算法 | 阈值 |
|---|---|---|
| 像素密度一致 | 读 `.tscn` 里各节点的累计 scale × 贴图格尺寸，换算出每个素材像素在屏幕上占几个像素，各节点必须一致 | 全部相同 |
| 整数倍放大 | 读 `project.godot`：`display/window/stretch/scale_mode = integer`，以及 `rendering/2d/snap/snap_2d_transforms_to_pixel` 和 `snap_2d_vertices_to_pixel` | 像素风必须开启 |
| 视觉焦点 | 主体与周围一圈的局部明度对比（OKLab L）。主体框由 `shots.json` 标出 | ≥ 0.15 |
| 明度层次 | 按节点所在的 CanvasLayer / 视差层分出前、中、背景，比较前景和背景的中位 L；全局取 5–95 百分位跨度 | 差 ≥ 0.2；跨度 ≥ 0.6 |
| 景深饱和度 | 背景的平均 C 比前景低 | 低 30% 以上 |
| 色温 | 每个物体取 L 最高的 15% 和最低的 15% 像素（去掉描边、alpha 边缘、UI），高光的平均 b 减阴影的平均 b；各物体的符号必须一致 | ≥ 0.02 |
| 主色相 | 所有素材合计的色相直方图，主色相簇的数量与覆盖率 | ≤ 3 簇，覆盖 ≥ 80% |
| 调色板偏离率 | 不透明像素中离色板最近色 ΔE > 阈值的比例 | 像素风为 0 |
| 剪影 | 生成剪影图（不透明像素填黑），交给评审模型判断能否辨认 | 由评审模型判 |

## 3. LUT 后处理

- **调色**：WorldEnvironment 的背景模式设为 Canvas，打开 `adjustment_enabled`，`adjustment_color_correction` 指向一张 LUT。不用写 shader，Light2D 在这一步之前已经算完，两者不冲突。UI 放在高于 `canvas_max_layer` 的 CanvasLayer 上，不受影响。
- **LUT 的来源**：在 OKLab 里把画面的均值和方差匹配到参考图，烘焙成 LUT 贴图，存在 `res://assets/style/grade_lut.png`。
- **暗角**：全屏 ColorRect 加 shader，读 `screen_texture`。
- **像素风**：LUT 和暗角都在视口分辨率上做，暗角按 3–4 档分级，最后量化回调色板（shader 读色板贴图）。否则会混入色板外的颜色，等于自己破坏了色板。
- **非像素风**：LUT 叠在第 5 步的色阶偏移之上，不替代色阶（见待实测 1）。

## 4. 截图评审闭环 `art_review`

### 机位

`.gdbox/art/shots.json`，所有评审都在这些机位上截图，改前改后才能对比：

```json
[
  { "name": "首屏", "scene": "res://main.tscn", "frames": 30, "subject": [120, 80, 40, 60] },
  { "name": "战斗", "scene": "res://levels/arena.tscn", "frames": 120 }
]
```

`subject` 是主体框（x、y、宽、高，视口坐标），给"视觉焦点"指标用。没有这个文件时默认取主场景的第 30 帧；第一次评审时由 Agent 补上。之后机位只能由用户修改，或者在新增场景时追加。

### 可复现

- 截图时固定 `--rendering-method` 和 `--resolution`。渲染器和 Godot 版本写进评审记录，不同渲染器下的分数不互相比较（没有显卡时会从 Forward+ 回退到 Compatibility，两者的 2D 光照结果不同）。
- 每个机位截两次，比较哈希。不一致的标为"不稳定"，不参与冠军比较。原因是游戏里的随机数不设种子，粒子在循环发射时也无法完全复现。
- `--quit-after N` 会把 N 帧全部编码成 PNG，所以机位的帧数尽量小。
- `--headless` 拿不到帧，不能用。

### 评分维度

顺序固定；前面的维度不及格时，这一轮只修前面的维度。

| 维度 | 判法 |
|---|---|
| 剪影与可读性 | 评审模型看剪影图和灰度图 |
| 明度与视觉焦点 | 代码指标：焦点、明度层次、景深饱和度 |
| 比例与像素密度 | 代码指标：像素密度、整数倍放大 |
| 线条与风格一致 | 评审模型对比参考图：描边有无、写实或扁平、细节程度是否统一 |
| 色彩 | 代码指标：主色相、色温、偏离率 |
| 细节密度 | 评审模型：疏密变化、有没有大片空白或满屏噪点 |
| 光向（抽查） | 评审模型，只报告，不计分 |

评审模型输出：

```json
{
  "scores": { "剪影与可读性": 6, "线条与风格一致": 5, "细节密度": 7 },
  "vs_best": "better | worse | same",
  "fixes": [
    { "dimension": "线条与风格一致", "where": "敌人", "do": "敌人没有描边，其他素材有 1px 深色描边；重新加工时补上" }
  ]
}
```

代码指标的结果和评审模型的结果合并成一份报告。`fixes` 只针对得分最低的两项，每条写清位置和具体改法。结果追加到 `.gdbox/art/reviews.jsonl`，每条记录带评审模型 id、渲染器、Godot 版本、机位、截图路径、分数和快照 commit。

**先修构图和可读性，再加特效**：前两个维度有不及格时，这一轮不允许加后处理、粒子或光效。

### 循环控制

- 以 `vs_best` 两两比较为主、绝对分为辅。同一模型重复评分的一致性一般（ICC 0.555），两两比较更可靠（见待实测 7）。
- 初稿所有维度都及格、且总分 ≥ θ 时，不进入循环。θ 先取 7.5，有数据后改成本工程历史分数的第 80 百分位。
- 否则最多 2 轮，与 `MAX_REVIEW_FIX_ROUNDS` 一致；第 2 轮后仍然不过，交给用户决定。
- **保留最好版本**：每次 `vs_best = better` 时，把当前快照 commit 记为该机位的冠军（复用 `snapshots.ts`，指针放在 `.gdbox/art/champion.json`）。循环结束时如果最后一版不是冠军，提示 Agent 回滚到冠军。
- 机位之间的分数不比较。

### 评审模型

- 设置里单独配置"美术评审模型"，默认取当前对话模型中支持图片输入的那个。
- 固定使用一个模型。换模型后，之前的分数不再参与 θ 和冠军的比较（按模型 id 分开统计）。
- 生成和评审尽量用不同的模型；用户只配了一个视觉模型时允许相同，但在记录里标出来。

### 和现有机制的衔接

- 隐私：`art_review` 加入 `VIEWPORT_CAPTURE_TOOLS`，截图开关关闭时整个工具从工具池移除。
- 团队模式：美术评审队员调用 `art_review`，按结论给 VERDICT（所有维度及格 → PASS），其余沿用 `reviewLoop`。
- 技能：在 `godot-art-style` 和 `godot-2d-character` 的最后一步加上"跑 `art_review`"。

## 5. 色阶色板

### 结构

`StylePack` 新增 `ramps?: string[][]`：每组按从暗到亮排列。`palette` 保留为所有色阶展开后的结果，兼容现有代码。

| | 像素风 | 非像素风 |
|---|---|---|
| 组数 × 阶数 | 3–5 组 × 4–6 阶 | 同左 |
| 颜色总数 | 全工程 ≤ 32；单个精灵 12–16，超出时报警告 | 不限 |
| 共用 | 各组共用最暗和最亮的一阶 | 同左 |
| 映射 | 按色相硬分配到某一组，再按 L 落到该组最近的一阶（snap） | 按色相硬分配到某一组；L 只做单调曲线映射；在该组内部只在 a/b 平面上做软分配（k = 3，权重 exp(−ΔE²/σ²)，σ ≈ 0.05），强度 0.3 |
| 抖动 | 只允许图块手动开启 `bayer4`；精灵上动画帧之间会闪 | 不用 |

色阶生成规则（OKLCH）：L 在 0.15–0.95 之间等距；暗端色相朝蓝紫偏 15–30°，亮端朝黄偏 10–20°；C 在中间阶最高，两端各降 30–50%。

### 来源

- `palette_from`：先按色相聚类，再在每个簇里补齐明度两端，不再按频次取前 16 色。按频次取色会丢掉高光和暗部，而且色源通常只有主角样张，缺少环境色。
- `palette_from_lospec: "<slug>"`：从 `lospec.com/palette-list/<slug>.hex` 取色，再按色相自动分组、按 L 排序。

### `art_palette_check(paths?, fix?)`

列出 `res://assets/` 下每张贴图的偏离率和颜色数。`fix: true` 时按上表处理，原图备份到 `.gdbox/history/`。覆盖用户放进来的图、素材包和 `generate_image` 的结果。

### 单测

- 暗蓝不被映射成灰。
- snap 后偏离率为 0。
- 非像素风映射后明度保持单调：原图更亮的像素处理后仍然更亮。L 只做单调曲线映射，这一条由构造保证。
- 1px 的眼睛和描边在 alpha 二值化后仍然保留。

## 6. 场景光照

新技能 `godot-2d-lighting`，写 `.tscn` 文本，不做成工具：

- `CanvasModulate` 压暗环境，色温和 `lighting.keyColor` 互补。
- 光源用不带法线的 `PointLight2D`：没有法线贴图时，Light2D 照样按纹理叠加或调制。像素风的光照贴图用 3–4 档的阶梯渐变，不用平滑渐变。
- 最多一盏灯开阴影。UI 和背景用 `light_mask` 排除。
- 遮挡直接写进 `tilesetTres` 的 occlusion layer，不用单独摆 LightOccluder2D。
- 限制：每个 CanvasItem 最多受 15 盏灯影响，超出的被静默忽略；Light2D 只照亮同一个 CanvasLayer，放在其他层的视差背景照不到。
- 最后跑 `art_review`，重点看明度与焦点、色彩两项。

## 7. 法线贴图（可选）

进入条件：在夹具上和"只用 PointLight2D"做人工盲比，赢了才进。

- 法线来源：接深度估计或法线生成模型，或者导出给 Laigter 手调。不用距离场算法。
- 要求 Godot ≥ 4.2（TileSetAtlasSource 使用 CanvasTexture 带法线的问题在 4.2 修复）。
- 嵌套方向：每帧的 AtlasTexture 把 `atlas` 设成 CanvasTexture；反过来在 CanvasTexture 里放 AtlasTexture，region 会失效。
- 过滤在 CanvasItem 或 CanvasTexture 的 `texture_filter` 上设置；Godot 4 的 2D 导入没有 sRGB 开关（初稿写错了）。
- DirectionalLight2D 的 `height` 默认是 0，这时法线效果很弱；它也不看 `light_mask`。

| 3 | 像素格估计在不规则格子（6.5–8.5px 一格）上是否可靠 | 估计不可靠时退回众数降采样 | 用 `keepRaw` 里的历史原图跑一遍，看估计结果和退回的比例 |
| 4 | Compatibility 渲染器是否支持 WorldEnvironment 的 adjustment | 假设支持 | 两个渲染器各截一张对比 |
| 5 | Windows 多显示器下，窗口放在 `10000,10000` 时会不会被拉回屏幕或停止渲染 | 沿用现有做法 | 双屏机器上跑 `godot_screenshot` |
| 6 | 同一机位截两次的哈希不一致的比例 | 不一致的标为不稳定 | 在三个现有工程上统计 |
| 7 | 两两比较是否比绝对分更稳定 | 两两比较为主 | 同一组截图各评 3 次，比较一致性 |
| 8 | AtlasTexture(atlas = CanvasTexture) 在 AnimatedSprite2D 运行时能否显示（论坛有 4.4 上"编辑器里正常、运行时空白"的报告） | 只有做第 7 步时才需要 | 最小工程实测 |
| 9 | CanvasTexture 默认的高光会不会让像素图发亮 | 只有做第 7 步时才需要 | 同上 |

## 整体验收

夹具任务："做一个平台跳跃游戏的首屏，有主角、地面、背景和一个敌人"。

| 组 | 条件 |
|---|---|
| 对照 | 当前 main |
| 实验 | 第 1–6 步全开 |

- 自动指标：第 2 节的全部代码指标、`art_review` 各维度分数（固定评审模型和渲染器）、生图费用、总耗时。
- 人工盲评：视觉模型评审的有效性没有经过人工验证，所以最终以人工两两盲比为准，每组至少 5 次运行。

## 这一轮不做

- 风格 LoRA 训练（Scenario 这一类），以后在 `art_style` 里留接口。
- 手感组件库（震屏、命中停顿、补间动画）。
- 3D 美术。
- 锯齿检测、帧间一致性检查、内描边 selout。
