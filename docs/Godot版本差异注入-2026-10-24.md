# 按工程 Godot 版本注入版本差异 — 方案

## 要解决的问题

模型对 Godot 4.3 及以前很熟，对 4.4–4.7 的改动知道得少，而且会两头错：

1. **工程版本比模型认知新**：照旧版行为写代码，不报错但结果不对。
   例：4.7 把 `AudioStreamPlayer3D.area_mask` 默认值从 1 改成 0，Area3D 的总线覆盖静默失效。
   GodotPrompter 的对照评测里，不给这条信息时模型 3 次全错。
2. **工程版本比模型认知旧**：在 4.3 工程里用了 4.4+ 才有的写法（typed Dictionary、`@abstract`、可变参数），
   `godot_check` 报错后模型不知道原因，换着写法反复试。

## 现有基础

- `src/main/godot/projectFile.ts` 已从 `config/features` 解析出 `engineVersion`（如 `"4.7"`）。
- `createAgent.ts` 的 `describeProject` 已把 `(Godot 4.7)` 写进系统提示词末尾的 `<environment>`；
  `runtimeEnvelope.ts` 每轮信封里也有。
- 版本随会话绑定的工程变化，系统提示词本来就会随之变化，注入一段按版本挑选的内容不增加额外的缓存失效。

## 设计

### 1. 数据：`src/main/godot/versionNotes.ts`

用 TS 数组存，类型检查即校验，不写加载器。每条：

```ts
interface VersionNote {
  since: '4.4' | '4.5' | '4.6' | '4.7'   // 改动出现的版本
  kind: 'changed' | 'added'              // changed = 旧写法行为变了；added = 新 API
  summary: string                         // 给模型看的一句话，英文，≤160 字符
  patterns?: RegExp[]                     // 匹配报错用；静默类改动没有报错可匹配，不填
  source: string                          // 迁移指南或 PR 链接
}
```

收录标准：**模型照旧习惯写会出错**的才收。纯新增功能只在「旧工程不能用」时有意义，收成 `added`。
渲染设置默认值、导出选项这类模型很少碰的，不收。

来源：
- 4.7：GodotPrompter 的 33 条（MIT，按条核对后改写，在 `THIRD-PARTY-NOTICES.md` 署名）。
- 4.4 / 4.5 / 4.6：官方 `upgrading_to_godot_4.x` 迁移指南，自己改写。
- 能用引擎验证的默认值类条目（`area_mask`、`LookAtModifier3D.relative` 等），写个脚本用本机引擎
  `ClassDB.class_get_property_default_value` 核一遍，防止抄错。

预计总量 30–40 条。

### 2. 第一层：系统提示词 `<environment>` 里加一段

`buildEnvironmentSection` 在已知 `engineVersion` 时追加：

```
Godot 4.7 behaves differently from what older material describes:
- AudioStreamPlayer2D/3D.area_mask defaults to 0; Area audio_bus_override needs it set to 1.
- Overrides of a typed-return method inherit the return type; a missing return is an error.
- ...
Not available before 4.5: @abstract, variadic functions (...args).
```

挑选规则：
- `changed`：`BASELINE < since ≤ 工程版本`。BASELINE 定为 4.3，即模型可靠掌握的最后一版。
- `added`：`since > 工程版本`，只列名字和版本，一行一组。
- 版本比较按数字逐段比（`4.10 > 4.9`），不按字符串。
- 硬上限约 2.5 KB（约 600 token）。超出时按条目顺序截断，数组顺序即优先级，最常踩的排前面。
- 工程版本未知、或 ≤ 4.3 且无 `added` 可列时，这段不出现。

### 3. 第二层：`godot_check` / `godot_run` 报错时补充

`tools/godot/runtime.ts` 拿到引擎输出后，用 `patterns` 匹配报错和警告行；命中且该条适用于
**实际运行的引擎版本**（`godot --version`，不是 `config/features`，因为报错是这个引擎打的）时，
在工具结果末尾附上那条 `summary` 和 `source`。

只匹配符号名不够：4.7 的「override 继承返回类型」报的是 `Not all code paths return a value`，
里面没有任何符号，所以用正则，原文取自本机 4.7.1 的真实输出。

这一层只在真出错时付费，符合 `buildSystemPrompt` 注释里「能在工具返回里说清楚的就不写进提示词」的原则。
它也兜住第一层被截断的条目。静默类改动（如 `area_mask`）不会出现在报错里，所以第一层仍然需要。

### 不做

- 不做成 skill：skill 靠 description 匹配触发，GodotPrompter 自己测出过只触发 1/3 的情况，
  而版本差异恰恰是模型「不知道自己不知道」的东西。
- 不加查询工具：第一层的一句话已经够用，第二层补出处。真机评测证明不够再加。
- 不处理「工程声明 4.3、本机绑定的引擎是 4.7」的错配，那是引擎选择的问题，另开。

## 验证

- 单测：挑选规则（版本区间、`4.10` 比较、上限截断、未知版本不出段）；
  `createAgent.test.ts` 的环境块矩阵加一维版本；数据自检（summary 长度、source 非空、symbols 非空、since 合法）。
- 第二层单测：用真实的 4.7 报错文本（`type_exists` 废弃警告、`textureQueryLod` 编译错误）验证命中。
- 真机对照：借 GodotPrompter 的 skill-10（4.7 下 Area3D 水下总线不生效）和一条
  「4.3 工程里写 typed Dictionary」的用例，开关各跑 3 次，看答案是否点出版本原因。

## 待定

1. BASELINE 用 4.3 还是 4.4。4.4 发布于 2025 年 3 月，较新的模型多少知道一些；定 4.4 能省约三分之一篇幅，
   但老模型会漏。建议 4.3。
2. 上限 2.5 KB 是否合适。

## 对照评测（2026-10-24）

只测第一层那段提示词本身。两组都带现有的环境行（`belongs to project Tunnel (Godot 4.7)`），
差别只在有没有版本差异段。模型是本机 Codex CLI 的默认模型，只读沙箱、空目录、不许查网，
按正则判分后人工复核。

| 用例 | 工程版本 | 判据 | 有 | 无 |
|---|---|---|---|---|
| Area3D 水下总线不生效 | 4.7 | 说出 `area_mask` 默认值是 0 | 3/3 | 0/3（全说默认是 1） |
| 只接收第一个手柄，`event.device != 0` | 4.7 | 说出键鼠不再是设备 0 | 1/3 → 改写后 4/5 | 0/3（全说键鼠也是 0） |
| 写带类型的背包脚本 | 4.3 | 不写 `Dictionary[K, V]` | 3/3 | 3/3 |
| `duplicate(true)` 不复制外部资源 | 4.7 | 给出 `duplicate_deep` | 3/3 | 3/3 |

- 拉开差距的是「默认值/行为改了但不报错」那类，和 GodotPrompter 的结论一致。
- 设备 ID 那条原来只写新值，模型多半没读出「所以 `device == 0` 不再匹配键鼠」；
  改成先说「no longer device 0」后 4/5 能说出来。条目要写出旧假设哪里失效，不能只写新值。
- 后两例两组都满分：这个模型本来就会，不能区分，只留作回归。
- 没测第二层（报错补充），它由单测覆盖匹配；也没测 gdbox 里实际配置的其他模型。
