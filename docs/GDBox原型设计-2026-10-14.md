# GDBox 设计稿

> 状态：M0–M4 已全部实现并提交（2026-10-14）。实际状态、和原设计的出入、还没验证的部分见文末「实现状态」。
> 依据：`H:\UnrealAgent\_gdbox-lab\第一轮汇总.md`（四个开发者 Agent 实地做 Godot 游戏的痛点）

## 一句话

GDBox 是给 Godot 开发者用的 AI 工作台。它是一个独立的开源桌面应用，自带 Agent。代码 AI 已经会写了，**GDBox 管的是代码以外的部分**：美术、音乐、音效、配音一生成出来就能直接放进游戏；改完会自己跑一遍、截图验收；风格和经验越用越多。

和虚幻盒子是**两个独立项目**：各自的仓库、品牌、版本和公司主体。需要的代码从虚幻盒子按块拷过来，拷完之后各自演进。

## 为什么用户需要它（大白话）

第一轮实验里，四个"开发者"用 AI 做 Godot 游戏，代码都写得很顺。时间全耗在了下面这些地方：

1. **生成的图不能直接用**。没有透明底、像素大小不一、帧没对齐，每个人都自己写了两三个脚本去加工。3D 模型的大小和朝向也是乱的。
2. **声音这块最缺**。没有音效生成；音乐不管时长、不能循环；配音所有角色都是同一个声音。
3. **AI 改完不知道游戏能不能跑**。每个项目都要重新搭一遍运行、截图、看报错的脚手架。
4. **东西不进工程**。生成物散落在好几个系统目录里，而且是哈希文件名。
5. **风格靠自觉，经验会丢**。只存在于导入设置和终端命令里的经验，下个项目就忘了。

GDBox 的第一版就从 1 到 3 开始做。

## 产品原则

- **勿增实体**：能放进对话里的就不另开页面；默认只显示必要的东西，其他按需出现。
- **生成即资产**：任何生成能力，最终交付的都是 `res://` 里能直接用的 Godot 资源，并且带一份结构化回执（路径、尺寸、时长、帧数等）。
- **改完就验**：Agent 改完工程，默认自己跑一遍、看报错、截图给你看。
- **本地优先、开源**：不要账号；本地功能离线可用；模型和生成服务由用户自己配置。
- **轻**：Godot 用户偏爱轻量，安装包和启动速度都算在体验里。

## 界面（第一版）

只有一个主窗口，分三块：

```
┌──────────┬───────────────────────────┬──────────────┐
│ 工程列表  │         对话              │  资产抽屉     │
│ （拖入    │  Agent 的过程和结果        │ （本次生成的  │
│ project.  │  截图、试听直接内嵌         │  图/音/模型， │
│ godot）   │                           │  预览和试听） │
└──────────┴───────────────────────────┴──────────────┘
```

- **首次启动**：找到 Godot（先自动找；找不到就让用户选一次 exe），然后把工程拖进来。
- **工程列表**：显示名字、图标、版本，全部从 `project.godot` 读。每个工程对应一组会话。
- **资产抽屉**：默认收起，有生成物时才弹出，没有就不占地方。
- **设置**：只有两项，模型服务和生成服务。

团队、素材库、风格包这些第一版都不出现在界面上。

## 架构

```
Electron 主进程
 ├── pi-coding-agent SDK（每个工程一个 AgentSessionRuntime，cwd = 工程目录）
 │     ├── 自带：会话持久化与分支、压缩、read/edit/write/bash 工具、技能、MCP、tool_search
 │     └── GDBox 扩展（我们写的代码，全部以 inline extension 注入）
 │           ├── godot-project   工程识别、系统提示词里的 Godot 段落、保护 .godot/ 等目录
 │           ├── godot-run       headless 检查、运行场景、离屏截图、日志过滤、自动试玩
 │           ├── aigc            生图、3D、音乐、音效、配音 + 后处理，产物写进 res://
 │           └── host-ui         审批、选择、通知，转发给渲染进程
 ├── Godot 定位与工程库（我们写）
 └── AIGC 服务商适配（从虚幻盒子拷）
Vue 3 渲染进程
 └── 对话界面、工程列表、资产抽屉、设置（订阅 session 事件流）
```

### 为什么建在 pi-coding-agent 上

`@earendil-works/pi-coding-agent` 1.2.0 已经提供了下面这些，虚幻盒子当年是自己写的：

| 能力 | pi 自带 | 虚幻盒子当年 |
|---|---|---|
| 会话持久化、分支、续跑 | `SessionManager`、`AgentSessionRuntime` | 自研 |
| 上下文压缩 | 内置 | 自研 |
| 读写改文件、命令行（含 PowerShell） | 内置工具 | 自研 |
| 技能 | Agent Skills 规范，支持项目级 `.agents/skills` | 自研加载器 |
| 工具按需加载 | `tool_search`、`exposure: deferred` | 自研常驻组和子组 |
| MCP | `pi-mcp` | 自研 |
| 扩展点 | `registerTool`、`pi.on('tool_call' / 'before_agent_start' …)`、`registerProvider` | 散落在 createAgent 里 |
| 结构化工具结果 | `outputSchema` + `structuredContent` | 没有（实验里 `structured: null` 就是这个问题） |

所以 GDBox 只需要写 **Godot 和 AIGC 这两类扩展，再加一个界面**。跟着上游升级就能拿到改进。

需要接受的代价：会话格式（JSONL）和事件模型是 pi 定的。如果 pi 的设计改了，我们跟着改。

### 关键接线

- `createAgentSession({ cwd: 工程目录, agentDir: <userData>/agent, modelRuntime, resourceLoader, settingsManager })`。
  `agentDir` 放在 GDBox 自己的 userData 下，**不和用户本机的 pi CLI 共用配置**。
- `ModelRuntime.create({ authPath, modelsPath })` 也指向 userData。API Key 由用户在设置页填写，存在本地。
- 资源加载用 `DefaultResourceLoader`，通过 `extensionFactories` 注入 GDBox 扩展，再加上内置技能目录 `resources/skills/`。
- SDK 会话默认不带 tool_search 和 MCP，需要显式加 `createToolSearchExtension()`、`createMcpExtension()`。
- 扩展里的 `ctx.ui`（confirm、select、notify）由主进程实现，经 IPC 转给渲染进程弹窗。
- 审批规则按工具 annotations 判断（只读的直接放行，破坏性的要确认），写法照 pi 文档里的例子。

### 第一批 GDBox 工具

| 工具 | 做什么 | 返回 |
|---|---|---|
| `godot_check` | headless 导入加运行若干帧，默认 `--fixed-fps 60`；过滤已知的假报错（比如 4.7.x 播过音频后退出时的泄漏报告） | 真正的报错列表 |
| `godot_run` | 运行指定场景，可以注入输入序列（自动试玩），到时间自动退出 | 日志摘要 + 关键事件 |
| `godot_screenshot` | 离屏窗口截图，几秒内自动退出 | PNG 路径，并直接给模型看图 |
| `gen_sprite` | 生图 → 去背景 → 像素规整 → 切帧 → 写出 SpriteFrames `.tres` | 路径、帧数、尺寸、GIF 预览 |
| `gen_tileset` | 生图 → 切块 → 修描边 → 写出带碰撞的 TileSet `.tres` | 同上 |
| `gen_model3d` | 生成 glb → 体检 → 统一比例、原点、朝向 → 贴图降级 | 面数、尺寸（米）、贴图信息 |
| `gen_music` | 生成 → 按指定时长裁剪 → 找循环点 → 输出 ogg，并在导入设置里开启循环 | 时长、循环点 |
| `gen_sfx` | 一次生成几个候选音效 | 候选列表，在资产抽屉里试听 |
| `gen_voice` | 按台词表和角色音色表批量合成，增量更新 | 每行台词对应的文件 |
| `listen` | 让多模态模型听一段音频并描述（解决"AI 听不见"） | 文字描述 |

> 实现时 `listen` 改成了 `inspect_audio`，原因见文末「实现状态」。

产物一律写进工程（默认 `res://assets/gen/<类型>/`），文件名可读，并在工程里留一份生成记录：提示词、服务商、参数。这份记录就是以后"风格包"和"经验"的原料。

## 从虚幻盒子拷什么

**拷**（用到时再拷，文件头注明来源和 Apache-2.0）：

- AIGC 服务商适配：`src/main/ai/imageGeneration.ts`、`model3d.ts`、`music.ts`、`speech.ts`、`speechQwenAudio.ts`、`video.ts`（暂不需要），`agent-v3/tools/aigc/` 里的参考图上传、模型清单、扣费确认逻辑。
- 模型服务商的配置和凭据：`src/main/ai/credentials.ts`、`catalog*`、`providerKey.ts`。要和 pi 的 `ModelRuntime` 对接，属于改写，不能直接用。
- 音视频理解：`src/main/services/dashscope/`，`listen` 工具要用。
- 以后的资产库、经验、团队：等对应里程碑再拷，拷之前重新看一遍现状。

**不拷**：`createAgent.ts`、工具注册表、常驻工具和 toolSearch、技能加载器、会话存储。这些 pi 都已经有了。UE 相关的一切也都不拷。

### 和原设计的出入

- **`listen` → `inspect_audio`**：盘点发现虚幻盒子没有任何「听音频」的能力，接一个多模态音频服务又是一家新的付费依赖。改成离线测量能测的事实：时长、响度、削波、首尾静音、明暗、音高走向、循环接缝。模型仍然听不见「好不好听」，这一点在提示词里明说，由用户在资产抽屉里试听。
- **音效**：原设计只有 AI 音效。实现时加了离线 sfxr 合成（7 种复古预设，多候选，免费），没配 AI 音效服务也能用。
- **`godot_run` 的实现**：设计里写的是「注入输入序列、自动试玩」。实现成一个 SceneTree 运行器脚本（打进安装包里），临时放在 `.gdbox/tmp` 跑完删掉，不改用户工程；除了按键，还能按时间采样任意节点属性，这是模型验证行为时真正要的东西。
- **工具比原设计多**：`gen_image`（背景/道具/图标）、`style`、`remember`、`addon_library`、`scene_doctor`、`merge_help`、`review_changes`、`tasks`、`team_setup`，以及 7 个 `editor_*`。都来自第一轮实验的具体痛点。
- **经验**：没有另造存储。所有工程通用的经验写进 GDBox 自己 pi 目录下的 `AGENTS.md`，pi 在任何工程里都会加载它。
- **个人插件库**：原设计没有，来自老周「第二个项目复用自己的代码」的痛点：存的时候带版本号，装的时候自动配 autoload 和编辑器插件。
- **任务板不做界面**：一个任务一个 Markdown 文件，放在 `.gdbox/tasks/`，跟 git 走。Agent 通过工具读写，队友直接看文件。没有加新页面。

### 真实服务商实测（2026-10-14，用本机已有的模型配置做测试 Key）

| 能力 | 服务商 | 结果 |
|---|---|---|

| 生图（精灵、瓦片集、背景） | toapis `gpt-image-2.5-sunburst` | 修完后通过：狐狸 10 帧 3 段动画、6 块瓦片、16:9 背景，Godot 都能加载 |
| 音乐 | SUNO V6 | 通过：两首里挑出 37 秒循环（相似度 97%），Godot 导入即循环 |
| 配音 | 通义 Qwen-Audio 3.0 | 通过：两句，带音色 |
| 3D | Tripo P1 | 通过：约 150 秒，包装场景规整到 1 米高、带碰撞 |
| 生图 | 豆包 Seedream 5.0 | 通过：19 秒；背景给的是玫红不是纯品红，去背景照样干净 |
| 配音 | 豆包 Seed-TTS 2.0 | 通过：3.8 秒语音，不到 1 秒 |
| 看图验收 | Claude Sonnet 5（toapis 中转） | 通过：看截图说对了 HUD（金币 0/16、三颗心）和主角位置；32 像素小人的衣服颜色说得不全对 |

补做 `godot_run` 后再测一次「加二段跳并验证」（deepseek-flash，40 秒）：模型不再写临时测试场景，用 `godot_run` 跑了 4 次，分别验证了二段跳生效、没有三段跳、落地复位；还发现「代码里创建的节点没有固定路径，要用 `.:player` 这种写法读」，自己用 `remember` 记进了通用经验——M2 的经验沉淀在真实使用里第一次跑通。

实测修掉的问题：toapis 这类网关要「比例 + 分辨率档」，给像素尺寸会 503；比例被忽略导致背景出成正方形；10 帧排 4×3 网格时切帧误退回网格平分；抠像色粉边；设置页保存会丢已有服务商的 Key；截图前没导入资源，新工程截出来只有 HUD（看图模型如实说「看不到主角」才发现）。
